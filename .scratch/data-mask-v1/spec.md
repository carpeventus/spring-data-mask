# 数据脱敏 SDK（data-mask-spring-boot-starter）v1 规格

**Status:** ready-for-agent

> 来源：`requirements/v1/脱敏后端SDK.md` 与设计访谈结论（2026-10-10）。相关决策见 `docs/adr/0001`–`0004`，术语以 `GLOSSARY.md` 为准。

## Problem Statement

业务系统在 HTTP 接口中返回手机号、证件号、地址等个人敏感信息时，直接返回原文既暴露隐私又难以满足合规要求；同时存在"响应里给前端脱敏值，后续请求中后端还能按当前用户校验并还原原文"的场景。在没有统一机制时，开发者只能手工在 DTO 里拼装脱敏值：容易漏字段、规则不一致，也没有标准的可逆加密与批量解密做法。

## Solution

提供一个尽量零依赖（仅 Jackson）的 Spring Boot 集成件：接入方在 HTTP 接口方法上标注 `@SensitiveApi`、在 DTO 的 String 字段上标注 `@SensitiveData`，响应即按脱敏类型输出脱敏值；标注 `addCipherField = true` 的字段在同一层级额外输出一个 `<字段名>Cipher` 的密文字段。接入方通过两个扩展点提供当前用户与 AES-256 密钥；解密通过服务 Bean 按批还原，并校验密文归属（当前用户一致）与有效期。

## User Stories

1. 作为接入方开发者，我希望只添加一个 Maven 依赖并实现两个小接口就完成集成，以便无需手写配置类、不改动既有控制器逻辑。
2. 作为接入方开发者，我希望在接口方法上标注 `@SensitiveApi` 就开启该接口响应的脱敏处理，以便声明式的精细控制生效范围。
3. 作为接入方开发者，我希望没有标注 `@SensitiveApi` 的接口输出与引入前完全一致，以便安全上线。
4. 作为接入方开发者，我希望在 String 字段上标注 `@SensitiveData(type = …)` 声明该字段的脱敏类型，以便逐字段定义规则。
5. 作为接入方开发者，我希望 `EMAIL` 类型保留用户名首字符或前 1–2 位并保留域名，以便邮箱既可读又不完整暴露。
6. 作为接入方开发者，我希望 `PHONE` 类型的手机号保留前 3 位与后 4 位、中间打星，以便号码可辨识且不完整暴露。
7. 作为接入方开发者，我希望 `PHONE` 类型的座机号隐藏得更多（区号保留、号码只留后 4 位），以便固话场景同样安全。
8. 作为接入方开发者，我希望 `BANK_CARD_NO` 保留前 6 位与后 4 位、中间打星，以便卡号可核对且不完整暴露。
9. 作为接入方开发者，我希望 `ID_CARD_NO` 保留前 6 位与后 4 位、中间打星，以便证件号可核对且不完整暴露。
10. 作为接入方开发者，我希望 `ADDRESS` 只掩门牌级信息（栋/幢/号楼、单元、室、号中的数字，各固定两个星号），以便地址保持大体可读。
11. 作为接入方开发者，我希望 `ALL` 固定输出 8 个星号，以便对无特定规则的字段做兜底全掩。
12. 作为接入方开发者，我希望标注字段位于任意深度的嵌套对象中时也被处理，以便不必为脱敏调整 DTO 结构。
13. 作为接入方开发者，我希望 List/分页包装结构内每个对象上的标注字段都被处理，以便覆盖集合类返回。
14. 作为接入方开发者，我希望值为 null 或空串时原样输出，以便不误伤缺失数据。
15. 作为接入方开发者，我希望非空但不符合对应模式的值全掩（8 个星号），以便宁可多掩也不泄漏。
16. 作为接入方开发者，我希望 `@SensitiveData` 误标在非 String 字段上时立刻报错，以便配置错误尽早暴露而不是悄悄不脱敏。
17. 作为接入方开发者，我希望脱敏只作用于响应，以便请求入参链路完全不受影响。
18. 作为接入方开发者，我希望 `addCipherField = true` 时在同层级生成 `<字段名>Cipher` 密文字段，以便前端或下游凭密文请求后端还原。
19. 作为接入方开发者，我希望加密使用 AES-256-GCM 且同一明文每次加密得到不同的密文串，以便密文不可被简单关联。
20. 作为接入方开发者，我希望解密接口接收密文列表并按顺序返回等长的明文列表，以便接入方自行做后续处理。
21. 作为接入方开发者，我希望解密单次最多接受 50 条密文，以便约束使用方式、避免滥用。
22. 作为接入方开发者，我希望解密时校验密文归属的当前用户与请求方一致，以便密文不能被其他用户使用。
23. 作为接入方开发者，我希望解密时校验密文未超过配置的有效期，超期返回"密文失效"，以便限制密文的流转时间。
24. 作为接入方开发者，我希望任意一条密文失败时整批解密失败（不做部分成功），以便处理逻辑简单明确。
25. 作为接入方开发者，我希望失败以带错误码的异常抛出，以便我自行转换为 HTTP 响应（状态码与文案由我决定）。
26. 作为接入方开发者，我希望实现 `CurrentUserProvider` 提供当前登录用户，以便 SDK 把它写进密文并在解密时校验。
27. 作为接入方开发者，我希望实现 `CipherKeyProvider` 提供 32 字节 AES 密钥，密钥来源（配置/KMS/远端）完全自主，以便不向 SDK 暴露秘密的存放方式。
28. 作为接入方开发者，我希望用 `data-mask.enabled` 一键关闭 SDK 而不用拆包，以便线上应急。
29. 作为接入方开发者，我希望用 `data-mask.cipher-expire-time` 配置密文有效期（默认 24 小时），以便匹配业务时效。
30. 作为接入方开发者，我希望缺少扩展点实现时应用启动即失败并给出清晰提示，以便配置错误在部署早期暴露。
31. 作为接入方开发者，我希望 SDK 兼容 JDK 8 且在 Spring Boot 2.7 上验收，并尽力兼容 Boot 3，以便存量与增量应用都能接入。
32. 作为接入方维护者，我希望 SDK 自身依赖极少（除 Jackson 与 Spring 集成骨架外不引入额外库），以便不污染接入方的依赖树。
33. 作为潜在使用者，我希望它以 MIT 协议开源，以便在商业项目中放心引入。

## Implementation Decisions

- **形态与坐标**：单 Maven 模块；坐标 `io.github.carpeventus:data-mask-spring-boot-starter`；Java 包 `io.github.carpeventus.datamask`；起步版本 `0.1.0-SNAPSHOT`；MIT 协议（沿用仓库现有 LICENSE）。
- **兼容基线**：编译目标 JDK 8 字节码（本机以 `--release 8` 交叉编译）；验收环境为 Spring Boot 2.7.x；实现刻意不触碰 servlet 的 `javax`/`jakarta` 类型，并同时携带 `spring.factories` 与 `AutoConfiguration.imports` 两种自动装配注册文件，Boot 3 为尽力兼容（详见 ADR-0004）。
- **拦截机制**：`@SensitiveApi` 命中时给请求打标记（在 MVC 前置阶段读取 HandlerMethod 注解并写入请求作用域），Jackson 序列化 `@SensitiveData` 字段时输出脱敏值；未命中标记时沿用默认 String 序列化，零额外开销（详见 ADR-0001）。`addCipherField` 的密文字段在同一序列化点作为兄弟字段写出。
- **注解契约**：`@SensitiveApi` 为方法级、无属性；`@SensitiveData` 为字段级，属性 `type`（枚举 `EMAIL`/`PHONE`/`ADDRESS`/`BANK_CARD_NO`/`ID_CARD_NO`/`ALL`）与 `addCipherField`（默认 `false`）。仅对 String 字段生效。
- **脱敏规则**（星号数量除注明外按 1:1 替换原字符）：
  - `ALL`：固定 8 个 `*`；
  - `BANK_CARD_NO`/`ID_CARD_NO`：保留前 6 位与后 4 位，中间换 `*`；
  - `EMAIL`：用户名长度 ≤3 只保留首字符，≥4 保留前 2 位，其余换 `*`；`@` 后域名原样保留；
  - `PHONE`：以 `1` 开头的 11 位纯数字按手机处理——保留前 3 位、后 4 位，中间 4 位换 `*`；其余（含 `-`、以 `0` 开头、其他位数）按座机处理——含分隔符时区号原样保留、号码部分只保留后 4 位，无分隔纯数字只保留后 4 位，其余换 `*`；
  - `ADDRESS`：仅门牌级数字（`栋`/`幢`/`号楼`、`单元`、`室`、`号` 前的数字）各替换为固定 `**`；省/市/区县、道路名、小区名不掩。
- **边界行为**：null 或空串原样输出；非空且不符合模式的值整体输出固定 8 个 `*`；`@SensitiveData` 标注在非 String 字段上时抛出异常。
- **加密契约**：AES-256-GCM；每次加密随机生成 12 字节 IV；密文串为 URL-safe Base64（无 padding）编码的 `IV ‖ 密文体 ‖ 认证标签(16B)`，不携带版本字节（密文有效期短，格式演进成本低）；明文载荷为 Jackson 序列化的 JSON `{"p", "u", "t"}`（`p` 原始字段值、`u` 当前用户、`t` epoch 秒）。
- **密文字段命名**：固定为 `<原字段名>Cipher`，不可配置。
- **解密契约**：`DataMaskCipherService#decrypt(List<String>)` 返回等长明文列表；顺序与输入一致、不做密文到明文的映射；单次最多 50 条；校验 `u` 与当前用户一致、`t` 未超有效期；任一条失败整批失败。错误统一为 `DataMaskException` 携带错误码（如密文失效、用户不一致、密文损坏、超出条数上限）。
- **扩展点**：`CurrentUserProvider#currentUserId()` 与 `CipherKeyProvider#cipherKey()`（32 字节，长度不符直接报错），以 Spring Bean 注入；SDK 不缓存密钥或用户（需要缓存由接入方在实现内自行处理）；启用状态下缺失 Bean 则启动失败（详见 ADR-0002）。
- **配置**：`data-mask.enabled` 默认 `true`；`data-mask.cipher-expire-time` 默认 `PT24h`（兼容 `cipher_expire_time` 写法，Spring 宽松绑定）。密文字段后缀与解密条数上限为固定常量，不提供配置。
- **时钟**：有效期判断使用可注入的 `Clock`（默认系统时钟），使超期行为可测试。
- **SDK 不注册任何 HTTP 接口**：解密只通过服务 Bean 提供（详见 ADR-0003）。

## Testing Decisions

- **好测试的标准**：只验证公共接口的外部行为（给定请求/输入 → 断言输出 JSON 或返回值），不断言内部结构、不 mock 内部协作者；期望值使用独立来源（已知好字面量），不使用按实现重算的期望。
- **Seam 1 · HTTP 集成（主）**：测试作用域内最小 Spring Boot 测试应用 + MockMvc（完整 MVC 栈）。覆盖：注解命中/未命中、六种脱敏类型的规则与示例、深层嵌套与 List、密文字段生成、null/空与不匹配的边界、非 String 报错、响应专属（请求不受影响）。
- **Seam 2 · 服务 Bean**：直接注入 `DataMaskCipherService`。覆盖：等长有序、≤50 上限、用户不一致、超期（配可注入固定时钟）、密文损坏、同明文两次加密不同；并与 Seam 1 的响应密文组成"加密 → 解密"闭环。
- **Seam 3 · 自动装配/启动**：`ApplicationContextRunner`。覆盖：缺扩展点且启用时启动失败且报错可读、`enabled=false` 跳过校验、配置绑定与默认值（默认 `PT24h`、显式 `PT12h` 生效）。
- **不单独设 seam**：内部算法类（各脱敏策略、加解密工具）不直接测试，"接口即测试面"。
- **先例**：仓库尚无代码与既有测试，无历史先例可循；采用标准 Spring Boot 测试组合（`spring-boot-starter-test`）。
- **环境**：本机 JDK 21 + Maven 3.9.16，编译 `--release 8`、测试跑在 JDK 21；多 JDK 矩阵留给以后 CI，如遇兼容问题回退 Maven toolchain。

## Out of Scope

- 发布到 Maven 中央仓库（Sonatype 账号、GPG 签名、发布流水线）——v1 后单独立项，可用 `/wizard` 处理只有人工能做的步骤。
- CI 流水线与多 JDK 测试矩阵。
- 官方支持 Spring Boot 3（仅尽力兼容，不验收）。
- 请求参数脱敏、日志脱敏、RPC 接口。
- 密钥轮换与密文版本字节。
- SDK 内置 HTTP 解密接口。
- 独立 sample/demo 模块。
- 新增第三个注解。
